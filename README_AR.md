# AI 3D Studio — مشروع تحويل الصور إلى مجسمات

واجهة ويب عربية متعددة الصفحات تستخدم **Microsoft TRELLIS.2-4B** لتوليد أصل ثلاثي الأبعاد بخامات PBR من صورة مرجعية، ثم تعرض ملف GLB في عارض Three.js وتتيح تنزيله. فصلنا الواجهة عن محرك الاستدلال حتى تعمل المعالجة على خادم GPU بينما يستخدم الزائر الهاتف للرفع والمعاينة فقط.

> **حدّ مهم:** مسار TRELLIS.2 الرسمي في هذا المشروع يقبل صورة مرجعية واحدة. إذا رفعت لوحة فيها زوايا كثيرة، استخدم أداة القص داخل الواجهة لاختيار لوحة واحدة كاملة. لا يتم دمج الزوايا الأخرى داخل النموذج. ولإعادة بناء هندسة حقيقية من صور كثيرة، تحتاج إلى مسار متعدد الصور/Photogrammetry منفصل، لا مجرد رفع الكولاج.

## ما الذي يتضمنه المشروع؟

- `web/index.html`: الاستوديو الرئيسي، عربي RTL، اختيار الصورة وقصّها، إعدادات الدقة، الحالة، المعاينة والتنزيل.
- `web/guide.html`: نصائح لصور الإدخال وإعدادات الجودة.
- `web/privacy.html`: شرح تدفق الملفات والاستضافة.
- `web/app.js`: رفع الصورة ومتابعة المهمة.
- `web/viewer.js`: عارض Three.js مع رسم عند الحاجة لتقليل استخدام GPU في الهاتف.
- `backend/server.py`: FastAPI API لإرسال المهمة ومتابعتها وتنزيل GLB.
- `scripts/setup_gpu.sh`: تثبيت المتطلبات في بيئة CUDA.
- `scripts/start_gpu.sh`: تشغيل الموقع وواجهة API.

## متطلبات الخادم

- Linux مع NVIDIA GPU وذاكرة فيديو لا تقل عن **24 GB** حسب المتطلبات المنشورة من مشروع TRELLIS.2.
- CUDA Toolkit 12.4 موصى به من المشروع الرسمي، وConda.
- مساحة تخزين كافية لتنزيل المستودع وأوزان النموذج وتخزين ملفات GLB.
- لا يمكن تشغيل نموذج 4B هذا على استضافة ملفات ثابتة أو هاتف Android وحدهما. الاستضافة التقليدية يمكن أن تقدّم الواجهة فقط؛ الاستدلال يحتاج إلى GPU في خادم منفصل.

المراجع الرسمية:
- TRELLIS.2: https://github.com/microsoft/TRELLIS.2
- مستودع أوزان النموذج: https://huggingface.co/microsoft/TRELLIS.2-4B
- وثائق FastAPI: https://fastapi.tiangolo.com/

## تشغيله على خادم GPU (الطريقة الأسهل)

1. أنشئ خادماً Linux مزوداً ببطاقة NVIDIA متوافقة، ثم ارفع هذا المجلد إليه.
2. ثبّت Git وMiniconda/Conda وتأكد أن `nvidia-smi` يعرض البطاقة.
3. من داخل مجلد المشروع نفّذ:

```bash
chmod +x scripts/*.sh
./scripts/setup_gpu.sh
cp .env.example .env
```

4. افتح `.env`، واجعل `APP_ACCESS_KEY` كلمة سر طويلة وفريدة. لا تترك القيمة الافتراضية. إذا وضعت البيانات في قرص دائم، حدّد `DATA_DIR` و`TRELLIS2_ROOT` بمسارات صحيحة.
5. شغّل الموقع:

```bash
./scripts/start_gpu.sh
```

6. افتح منفذ `7860` عبر إعدادات مزود الاستضافة، واستخدم HTTPS أو reverse proxy محمياً. عند فتح الواجهة، ضع قيمة `APP_ACCESS_KEY` نفسها في زر الإعدادات أعلى الصفحة.

> التثبيت الأول قد يستغرق وقتاً بسبب حزم CUDA، وتجميع بعض الإضافات، وتنزيل أوزان النموذج. أول عملية توليد قد تستغرق أكثر من العمليات التالية. لا تترك خادم GPU المستأجر يعمل حين لا تحتاجه.

## إعدادات الجودة

- `512³`: تجربة أولية أقل تكلفة.
- `1024³`: الخيار الافتراضي المقترح.
- `1536³`: أعلى تكلفة ذاكرة وزمن، وقد يتعطل إن كانت الذاكرة غير كافية.
- دقة الخامة 2048 أو 4096 بكسل وعدد الأوجه يحددان حجم ملف GLB وأداء العارض. الملفات عالية التفاصيل قد تكون ثقيلة على Redmi 14C حتى وإن نجح التوليد على الخادم.

المؤشر لا يدّعي نسبة دقيقة أثناء استدلال النموذج: تعرض الواجهة مرحلة التوليد بمؤشر متحرك لأن مسار الاستدلال المستخدَم لا يقدّم callback موثوقاً لنسبة الإنجاز.

## الاستضافة المنفصلة للواجهة والـ API

الأبسط تشغيل FastAPI والواجهة من الخادم نفسه. إذا استضفت الواجهة على نطاق مختلف:

1. اجعل `meta name="api-base"` داخل `web/index.html` يحتوي عنوان API العام، مثلاً `https://gpu.example.com`.
2. عيّن `CORS_ORIGINS` في بيئة الخادم إلى أصل الواجهة بالضبط، مثل `https://studio.example.com`.
3. انشر ملفات `web/` مع توجيه المسارات `/static/*` إلى ملفات الواجهة الموجودة في `web/`، ووفّر rewrites للمسارين `/guide` و`/privacy` إلى صفحتي HTML المناسبتين.
4. احمِ الـ API. لا تعتمد على إخفاء عنوان الخادم؛ `APP_ACCESS_KEY` حاجز إضافي بسيط وليس بديلاً عن إعدادات أمان الاستضافة وHTTPS.

## واجهة API

- `GET /api/health` — حالة الخدمة ووجود CUDA.
- `POST /api/generate` — إرسال صورة وإعدادات، يعيد `task_id`.
- `GET /api/tasks/{task_id}` — متابعة الحالة.
- `GET /api/tasks/{task_id}/preview` — ملف GLB لمعاينته.
- `GET /api/tasks/{task_id}/download` — تنزيل GLB.

تُرسل طلبات التوليد والتنزيل مع الترويسة `X-Access-Key` إذا كان `APP_ACCESS_KEY` مفعّلاً.

## ما المتوقع من الجودة؟

TRELLIS.2 نموذج صورة إلى 3D عالي الدقة بخامات PBR، لكنّه **توليدي**: لا يستطيع معرفة كل هندسة مخفية من صورة واحدة. قد يغيّر تفاصيل الجهة الخلفية أو المقاسات أو الأجزاء الرقيقة. إذا كنت تحتاج مجسماً مطابقاً لقطعة حقيقية، استخدم صوراً فوتوغرافية كثيرة متداخلة ومسار Photogrammetry، ثم افحص الشبكة في برنامج ثلاثي الأبعاد قبل استخدامها إنتاجياً.

## الأمان والاحتفاظ بالملفات

- افتراضياً، يكتب الخادم الملفات المؤقتة داخل `data/`.
- يحذف التطبيق الملفات القديمة عند وصول طلب توليد جديد بعد مرور 24 ساعة على آخر تحديث للمهمة. لا يُعد ذلك ضمان حذف جنائي؛ للمعلومات الحساسة استخدم تخزيناً خاصاً وسياسة حذف مناسبة.
- لا تنشره على الإنترنت العام من دون مصادقة وHTTPS وحدود استخدام على مستوى مزود الاستضافة أو reverse proxy.
- هذا المستودع لا يحزم أوزان النموذج ولا يغيّر ترخيص النموذج أو تبعياته. راجع تراخيص كل عنصر قبل أي استخدام تجاري.
